# 实验：从零实现一个链上积分合约

这个实验用一个最小但完整的 Solidity 合约，把“账户、状态、交易、权限、事件和回滚”串起来。所有测试都运行在 Hardhat 创建的临时本地 EVM 中：不连接主网或测试网，不需要钱包、私钥、测试币或真实资金。

> `LearningPoints` 是教学合约，不是完整的 ERC-20，也没有经过生产级安全审计。请勿直接用于真实资产。

## 你会学到什么

完成实验后，你应该能够解释：

- `mapping` 如何保存每个地址的积分余额；
- `msg.sender` 为什么代表本次调用者，而不是固定用户；
- `owner` 和 `onlyOwner` 如何限制发行权限；
- `mint` 与 `transfer` 分别怎样修改链上状态；
- `Transfer` 事件为什么便于区块浏览器和应用追踪变化；
- `revert` 为什么会让一次失败调用的状态修改全部回滚；
- 自定义错误怎样区分越权、零地址和余额不足。

## 环境与运行

需要 Node.js 22.13.0 或更高版本。进入本目录后执行：

```bash
npm install
npm test
```

已有 `package-lock.json` 时，也可以用 `npm ci` 获得完全一致的依赖。第一次安装依赖需要联网；项目固定并使用本地 `solc` 软件包，测试不再临时下载编译器，且只使用本机的临时网络。

看到 `8 passing` 就说明编译与全部测试均已通过。也可以分别运行：

```bash
npm run compile
npm run clean
```

## 先读懂合约

### 1. 所有权

部署合约时，构造函数把 `msg.sender` 保存为不可变的 `owner`。`onlyOwner` 修饰器在执行函数主体前检查调用者；不是 owner 就用 `Unauthorized` 回滚。因此只有部署者能够调用 `mint`。

### 2. 余额

`mapping(address => uint256)` 可以理解为“地址到非负整数”的表。未出现过的地址读取结果为 `0`，`balanceOf` 只读取这张表，不修改状态。通过钱包或节点在链下读取时不需要发送交易；如果另一个合约在链上调用它，读取操作仍会计入 Gas。

### 3. 发行和转账

- `mint(to, amount)` 增加 `to` 的余额，并发出一条从零地址到接收人的 `Transfer` 事件；
- `transfer(to, amount)` 从调用者扣除积分，再给接收人增加积分；
- 接收人不能是零地址，转出数量不能超过调用者余额；
- 成功的 `transfer` 返回 `true`，失败则回滚，不会留下“只扣款、未到账”的中间状态。

合约允许数量为 `0` 的发行或转账。这是刻意保留的简化规则；如果产品不接受零数量，可以再加入专门的校验和错误。

### 4. 事件不是余额本身

余额以合约存储中的 `_balances` 为准；事件是交易日志，供前端、索引器和区块浏览器高效检索。事件不能代替状态，也不会自动执行转账。

## 测试覆盖

`test/LearningPoints.t.sol` 每个测试前都会部署全新的合约，覆盖以下场景：

1. 部署者成为 owner；
2. owner 可以发行积分，并产生正确的 `Transfer` 事件；
3. 非 owner 发行时返回 `Unauthorized`；
4. 转账后双方余额正确，并产生正确事件；
5. 余额不足时返回 `InsufficientBalance`；
6. 向零地址发行或转账时返回 `ZeroAddress`；
7. 未持有积分的地址余额默认为零。

测试中的 `PointsActor` 是另一个合约地址，用来模拟“非 owner 用户”，不包含私钥，也不会连接任何外部网络。`vm.expectEmit` 是唯一使用的 Hardhat 测试辅助能力，用来检查事件内容。

## 建议的学习顺序

1. 先运行测试，确认环境正常；
2. 阅读 `LearningPoints.sol`，逐行写下注释中的“谁能调用、读取什么、修改什么”；
3. 在测试中把 `40` 改成 `101`，观察余额不足测试栈；
4. 暂时删掉 `onlyOwner`，运行测试并解释为什么越权用例失败；
5. 暂时删掉零地址检查，观察对应测试如何捕获规则缺失；
6. 恢复代码，尝试完成下面的扩展练习。

## 扩展练习

按由易到难的顺序尝试：

- 增加 `totalSupply`，并测试发行后总量变化、转账后总量不变；
- 增加 `burn(amount)`，允许用户销毁自己的积分；
- 增加 owner 转移机制，并认真处理新 owner 为零地址的情况；
- 给 `mint` 增加单次上限或总量上限；
- 最后再对照 ERC-20 接口，找出这个教学合约缺少的功能和兼容性要求。

每加一条规则，先写一个会失败的测试，再实现规则让测试通过。始终只在本地链或专用测试网钱包中实践，绝不把助记词或私钥写进代码、配置或命令历史。
