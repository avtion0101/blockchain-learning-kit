# 第 8 周：Layer 2、数据可用性与跨链桥

本周回答的问题是：**扩容方案把执行移到哪里，又把安全与可用性的代价留给了谁？**

## 学习目标

完成本周后，你应当能够：

- 分别定位交易执行、排序、数据发布、证明/挑战、结算和资产托管所在位置；
- 从验证机制解释乐观汇总与零知识汇总的核心差异；
- 解释数据可用性为什么是独立于“计算正确”的问题；
- 区分 Layer 2、侧链和其他链外方案，不把“兼容 EVM”当作继承 Ethereum 安全性；
- 为一个具体扩容网络和一座桥画出用户可退出性与管理员权限图。

## 核心概念

### 1. 模块化拆分

分析扩容网络时，把系统拆成四个问题：

- **执行**：谁运行交易并计算新状态？
- **数据可用性**：重建/验证状态所需数据放在哪里，谁保证能获得？
- **结算**：最终状态承诺和争议在哪里裁决？
- **共识/排序**：谁决定交易顺序，用户被审查时有什么替代路径？

“把交易发到 L2”只是开始。真正的安全判断来自这些职责的具体部署和当前权限。

### 2. 乐观汇总与零知识汇总

乐观汇总通常默认提交的状态转换有效，并提供挑战窗口与错误证明机制；零知识汇总提交可在结算层验证的有效性证明。两者仍需检查数据发布、证明系统、合约升级、排序器和退出路径；类别名称不能替代实例研究。

### 3. 数据可用性

即使状态承诺形式正确，如果验证者/用户拿不到重建状态所需数据，也可能无法独立验证或退出。数据放在 Ethereum、独立数据可用性层或运营方委员会，会带来不同成本与信任假设。

### 4. 跨链不是资产瞬移

常见桥接模型包括源链锁定、目标链铸造表示资产；或源链销毁、目标链铸造。用户需要信任消息验证、合约、签名者/验证者集合、升级管理员以及两条链的状态。桥失效时，目标链表示资产可能无法兑回原资产。

### 实践 B：研究一个具体扩容网络

从该网络的官方文档和部署清单开始：

1. 记录网络、研究日期、当前主版本和核心 L1 合约地址。
2. 找出排序器、批次提交者、证明者/挑战者和升级管理员。
3. 确认交易数据在哪里发布、多久发布、用户从哪里获得。
4. 画出“用户提交交易 → 排序与执行 → 数据发布 → 证明/挑战 → L1 结算”。
5. 找出正常提款所需步骤、等待条件和费用承担者。
6. 检查是否存在强制包含/强制退出路径；记录触发条件，而不是只写“有”。
7. 检查核心合约能否升级、由谁授权、是否有延迟或多签。
8. 使用第三方风险页交叉核对，并逐条回到官方或链上证据验证。

### 实践 C：推演数据被扣留

分别推演：

1. 状态根按时提交，但用户拿不到完整交易数据；
2. 排序器离线，但 L1 合约仍可访问；
3. 数据可用性委员会多数离线或作恶；
4. 证明系统正常，但升级管理员替换了核心合约。

对每种情况回答：能否验证最新状态、能否提交新交易、能否安全退出、资金是否立即损失、恢复依赖谁。避免把“暂时不可用”和“资产已被盗”混为一谈。

### 实践 D：拆解一座桥

选择该扩容网络的官方桥：

1. 从源链的原生资产开始，标出锁定/托管合约。
2. 标出跨链消息如何被确认、谁可以提交或验证。
3. 标出目标链收到的是原资产、包装资产还是账本余额。
4. 反向画出提款/赎回路径和时间条件。
5. 列出合约漏洞、验证者作恶、源/目标链重组、管理员升级、流动性不足等故障模式中适用的部分。
6. 回答：桥的目标链资产凭什么能够维持对源链资产的可赎回性？

## 验收问题

1. 交易执行正确与交易数据可获得为什么是两个不同问题？
2. 乐观汇总和零知识汇总以什么不同方式让 L1 接受状态更新？
3. 为什么使用 EVM 的侧链不自动继承 Ethereum 的共识安全性？
4. 排序器审查用户时，什么机制可能提供替代提交/退出路径？
5. “合约可升级”给修复能力和信任模型分别带来什么？
6. 锁定—铸造桥中，目标链表示资产的价值依赖哪些条件？
7. 运营方离线、数据不可用与恶意盗取是同一种失败吗？

判断标准：能够对一个具体网络逐项指出“在哪里发生、谁控制、怎样验证、失败时如何退出”，不以“它是 L2”作为安全结论。

## 安全提示

- 本周不需要跨链；跨链是高风险写操作，读文档和合约足以完成目标。
- 搜索结果中的“官方桥”广告可能是钓鱼站，从网络官方文档内进入并核对合约地址。
- 不把测试网桥接经验等同于主网风险评估；部署、权限和资产可能不同。
- 第三方风险评级是调查入口，不是代替独立核验的分数。
