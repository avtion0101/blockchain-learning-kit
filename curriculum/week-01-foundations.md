# 第 1 周：密码学与分布式系统直觉

本周回答的问题是：**一条消息为什么能够被验证、授权和共同记录？**

## 学习目标

完成本周后，你应当能够：

- 区分哈希、对称/非对称加密和数字签名的用途；
- 解释私钥签名、公钥验证意味着什么，以及它不证明什么；
- 解释节点、点对点网络、拜占庭问题与共识之间的关系；
- 用“可验证的状态更新”而不是“不可篡改数据库”描述区块链。

## 核心概念

### 1. 哈希：数据的固定长度指纹

密码学哈希函数把任意长度输入映射成固定长度输出。课程中主要使用三种直觉：

- 同一输入产生同一输出；
- 输入改变一点，输出通常显著改变；
- 从输出反推出输入、或找到两个输入产生同一输出，在合理资源内应当极难。

哈希不是加密：它通常没有用于还原原文的“解密密钥”。区块链用哈希连接区块、标识交易、汇总数据并方便验证完整性。

### 2. 密钥与数字签名：授权，不是保密

数字签名使用私钥产生签名，其他人使用对应公钥验证。验证成功通常说明：消息自签名后没有被改变，且签名者控制相应私钥。它不自动证明签名者的现实身份、签名时完全理解内容，或交易本身合法安全。

加密解决“谁能看”，签名解决“谁授权、内容有没有变”，哈希常用于“内容指纹”。三者可能组合使用，但不能互相替代。

### 3. 节点、网络与共识

节点是运行协议软件、接收并验证消息的计算机进程。点对点网络负责传播数据；共识规则负责让节点在消息延迟、故障甚至恶意参与者存在时，对有效历史和状态形成足够一致的判断。

共识不保证现实世界输入为真。例如，节点可以一致执行一个使用了错误价格的数据源。因此后续研究必须把“链内一致”与“链外事实正确”分开。

## 实践

### 实践 A：观察哈希的雪崩效应

1. 准备两段只差一个字符的文本，例如 `blockchain` 与 `blockchaiN`。
2. 完全在本地计算 SHA-256。PowerShell 可在终端分别执行：

   ```powershell
   $sha256 = [Security.Cryptography.SHA256]::Create()
   $bytes = [Text.Encoding]::UTF8.GetBytes("blockchain")
   $hash = $sha256.ComputeHash($bytes)
   [BitConverter]::ToString($hash).Replace("-", "").ToLower()
   $sha256.Dispose()
   ```

   macOS/Linux 可执行：

   ```bash
   printf %s blockchain | shasum -a 256
   ```

3. 修改一个字符后重复整段命令，记录输入与两个输出。
4. 再次计算原输入，验证输出稳定。
5. 写下实验能证明什么、不能证明什么。特别注意：两次输出不同不能证明“永远不可能碰撞”。

### 实践 B：签名的角色卡推演

三人分别扮演 Alice、Bob 和验证节点：

1. Alice 写下消息“向 Bob 转移 5 个学习积分”和唯一序号 `1`。
2. 用一张只有 Alice 保管的卡片代表私钥；用另一张公开卡片代表公钥。
3. Alice 对完整消息“授权”；节点依据公开卡片验证消息来自同一密钥持有者。
4. 分别篡改金额、接收人和序号，观察为什么原授权应失效。
5. 原样重放已授权消息，讨论为什么系统仍需要 nonce 或 UTXO 已花费检查。

这不是密码学实现，而是用于区分“签名验证”和“交易有效性验证”。

### 实践 C：四节点账本模拟

1. 画四个节点，每个节点初始账本相同：Alice 10，Bob 0。
2. 同时向不同节点传播两条冲突消息：Alice 向 Bob 转 8；Alice 向 Carol 转 8。
3. 写出各节点仅凭签名能确认的内容。
4. 再补充余额规则、交易排序规则与最终确认规则。
5. 说明为何“网络把消息传遍”不等于“网络已对唯一历史达成共识”。

## 验收问题

1. 为什么“知道一段数据的哈希”不等于“知道原始数据”？
2. 数字签名验证成功后，可以确认哪两件事？仍不能确认哪两件事？
3. 为什么一笔交易即使签名正确，也可能被节点判定无效？
4. 点对点网络和共识机制分别解决什么问题？
5. 如果所有节点都读取同一个错误预言机价格，共识是否仍可能正常工作？
6. “不可篡改”更准确的表述是什么？修改历史需要改变哪些条件？

判断标准：回答必须包含“授权不等于有效”“传播不等于共识”“链内一致不等于链外真实”三组区别。

## 安全提示

- 哈希实验只使用自造文本，不要拿密码、助记词或私钥做实验。
- 不要在在线“私钥生成器”或“签名演示器”中输入任何真实信息。
- 私钥控制权通常意味着资产控制权；截图、复制到云剪贴板或提交到代码仓库都可能造成泄露。
