# 第 4 周：EVM、节点、共识与状态转换

本周回答的问题是：**同一笔 Ethereum 交易为什么会在不同节点上得到相同结果，又何时可以认为结果足够稳定？**

## 学习目标

完成本周后，你应当能够：

- 用状态转换 `旧状态 + 有效交易 → 新状态` 解释 EVM；
- 区分执行层、共识层、执行客户端、共识客户端与验证者的职责；
- 解释内存、存储、calldata 和事件日志在入门层面的差异；
- 区分交易被广播、被纳入区块和达到协议最终性；
- 使用完全隔离的学习钱包在当前公开测试网发送一笔测试资产，并复核状态变化。

## 核心概念

### 1. EVM 是确定性的执行环境

所有正确实现协议的执行客户端，对于相同旧状态和相同有效交易序列，应计算出相同的新状态。智能合约不能随意访问网页、系统时间或外部数据库；链外信息要通过交易或预言机等机制进入链上。

合约的持久数据位于 storage；memory 通常只在一次调用期间存在；calldata 是调用输入的只读区域；事件日志便于链外程序索引，但合约不能把历史日志当作普通 storage 读取。

### 2. 执行与共识是不同职责

执行客户端验证交易并执行 EVM、维护状态；共识客户端跟踪权益证明共识并决定链头与最终性。完整 Ethereum 节点需要二者协作。验证者是参与提议/证明区块的角色，不是每个读取数据的用户都要成为验证者。

### 3. 最终性有明确语境

“交易已进区块”不等于“已经协议最终化”。短期链头可能变化；达到最终性后，逆转需要破坏更强的共识假设并承担相应惩罚。应用仍需根据业务风险决定何时向用户展示“已完成”。

## 实践

### 实践 A：在本地 EVM 观察状态变化

1. 从官方文档进入 [Remix](https://remix.ethereum.org/)，确认地址栏域名，不通过广告链接进入。
2. 使用 Remix VM（浏览器内本地模拟环境），不要连接钱包。
3. 打开 Remix 默认示例中的存储类合约；若界面示例变化，选择任何只有“写入一个数值、读取该数值”的最小合约。
4. 记录部署前后出现的合约地址与部署交易。
5. 先读取默认值，再发送写交易，最后读取新值。
6. 对照交易输入、Gas used、日志和 storage，写出哪些数据持久保存、哪些只是界面解释。
7. 重置 Remix VM，观察本地状态消失，并解释它与公共网络持久状态的区别。

### 实践 B：创建隔离的学习钱包

在做任何公开测试网操作前完成：

1. 新建只用于课程的浏览器配置文件，不安装其他扩展。
2. 从钱包项目官方站点进入扩展商店，交叉核对开发者名称、域名与扩展标识。
3. 创建全新学习钱包；不得导入真实钱包、复用真实钱包密码或复制真实助记词。
4. 将学习助记词离线保存，仅用于本课程恢复测试；不截图、不上传云盘、不写入学习记录。
5. 在钱包内建立两个学习账户 A、B，记录公开地址即可。
6. 先写一份“签名前检查表”：网络、目标地址、金额、方法、授权范围、预计费用。

### 实践 C：发送测试网交易并验证状态

1. 从 [Ethereum Networks](https://ethereum.org/developers/docs/networks/) 当前页面选择仍被官方文档支持的公开测试网，并记录网络名称、chain ID、确认来源与访问日期。
2. 仅使用该页面列出的可信入口获取少量免费测试资产。不要购买测试资产，不响应私信。
3. 记录账户 A、B 的交易前余额和 A 的 nonce。
4. 从 A 向 B 转移极少量测试 ETH，签名前逐项核对检查表。
5. 保存交易哈希；通过该测试网浏览器观察 pending、included 与后续确认/最终化信息（界面术语可能不同）。
6. 记录交易后两账户余额、A 的 nonce、Gas used、effective gas price 与实际费用。
7. 用余额变化解释为什么 A 的减少量不仅是发送给 B 的数额。
8. 若水龙头不可用，不向陌生人求币；保留失败证据，并在本地 EVM 复现同样的状态转换。公开测试网交易可以在获得安全渠道后补做。

## 验收问题

1. 为什么 EVM 合约不能直接发 HTTP 请求获取价格？
2. storage、memory、calldata 和事件日志分别适合保存或表达什么？
3. 执行客户端与共识客户端各自做什么？
4. RPC 服务商、节点和验证者是同一个概念吗？
5. 为什么多个节点能对一次合约调用计算出相同结果？
6. 测试网转账后，发送者余额减少量如何计算？nonce 如何变化？
7. 被纳入区块和达到最终性有什么区别？
8. 一个合约执行结果达到共识，是否说明它使用的链外价格一定正确？

判断标准：状态图必须同时出现“执行”和“共识”两条职责；测试网记录必须能从交易哈希复核，且不暴露任何秘密。

## 安全提示

- 只从官方网络文档进入水龙头与浏览器；测试网生态同样存在钓鱼链接。
- 领取测试资产不需要泄露助记词或私钥。要求输入秘密信息的页面必须立即关闭。
- 学习钱包永远不要接收真实资产；课程结束后可以弃用。
- 连接钱包不是浏览公开数据的前提；只有发送交易时才需要签名。
- 每次签名前先确认 chain ID。相同地址可出现在不同网络，网络选错会导致完全不同的结果。

## 离周门槛

从一笔自己的测试网交易出发，完整讲清“钱包构造并签名 → RPC 广播 → 执行客户端验证与执行 → 共识纳入/最终化 → 两个账户状态变化”，并指出 RPC 服务商不是你的私钥保管者，也不是共识本身。
