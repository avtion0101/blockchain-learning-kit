# 第 2 周：用 Bitcoin 理解交易、UTXO 与确认

本周回答的问题是：**在没有中央记账员时，Bitcoin 如何阻止同一份价值被花两次？**

## 学习目标

完成本周后，你应当能够：

- 把 Bitcoin 交易解释为“消耗旧输出、创建新输出”；
- 在区块浏览器中定位区块、交易、输入、输出、找零和手续费；
- 解释节点验证、工作量证明、链选择与确认之间的关系；
- 说明为什么交易已广播、进入内存池、进入区块和获得多次确认是不同状态。

## 核心概念

### 1. UTXO 不是账户余额

UTXO 是尚未被花费的交易输出。钱包展示的“余额”，通常是钱包能够使用的一组 UTXO 的总和。付款时，交易引用并完整消耗一个或多个旧输出，再创建收款输出和可能的找零输出。

在不考虑特殊交易的简化模型中：

```text
手续费 = 输入总额 - 输出总额
```

某个输出在有效链上只能被消费一次；节点会独立验证引用的输出是否存在、是否未花费，以及解锁条件是否满足。

### 2. 区块与工作量证明

区块头包含前一区块头的哈希，因此修改早期数据会改变后续链接。工作量证明使创建候选区块需要付出可衡量成本。节点不是因为“矿工说有效”就接受区块，而是自己检查共识规则；在多个有效候选历史之间，节点依据累计工作量选择链。

### 3. 确认是概率性置信度

交易第一次进入有效区块时获得 1 次确认；更多区块叠加后，重组并替换该历史所需的成本通常提高。确认数不是法律承诺，也不存在对所有金额、所有风险都适用的固定安全数字。

## 实践

本周全部为只读观察，不创建钱包、不购买 BTC、不广播交易。可使用公开浏览器，例如 [mempool.space](https://mempool.space/)，也可以选择其他浏览器交叉核对。浏览器是展示工具，不是协议本身。

### 实践 A：拆解一个区块

1. 在浏览器中选取一个近期、已获得多次确认的主网区块。
2. 记录区块高度、区块哈希、前一区块哈希、时间、交易数量和区块大小/重量。
3. 点击前一区块，验证高度连续且哈希对应。
4. 找到 coinbase 交易，并说明它和普通交易在输入来源上的差异。
5. 记录观察时间；稍后刷新并解释确认数为什么增长。

### 实践 B：拆解一笔普通交易

选择一笔包含至少一个输入、两个输出的非 coinbase 交易：

1. 记录 TXID、所在区块高度和确认状态。
2. 列出每个输入引用的前序交易输出及金额。
3. 列出每个新输出的金额与当前花费状态。
4. 计算输入总额、输出总额与手续费，核对浏览器显示。
5. 根据金额关系提出“哪个输出可能是找零”的假设，并明确它只是启发式判断，不能据此确认现实身份。
6. 任选一个输入沿前序 TXID 向前追踪一层，画出“旧输出 → 输入 → 新输出”。

### 实践 C：双花与确认推演

1. 假设同一个 UTXO 被两笔冲突交易 A、B 引用。
2. 写出节点收到 A 后会检查的至少四项规则。
3. 模拟不同节点先看到不同交易；解释内存池为何可以暂时不同。
4. 假设 A 先进入一个有效区块，说明 B 会怎样。
5. 再假设发生短暂链重组，讨论 A 的状态可能如何变化。
6. 分别从小额咖啡、交易所大额入账两个场景讨论可接受风险，不给出万能确认数。

## 验收问题

1. 为什么说“币从一个钱包文件移动到另一个钱包文件”不准确？
2. 一笔交易有 0.8 BTC 输入、0.3 BTC 收款输出和 0.499 BTC 找零输出，手续费是多少？
3. 为什么找零地址不能仅凭金额被百分之百识别？
4. 矿工可以把任意无效交易写入一个被全节点接受的区块吗？为什么？
5. “广播成功”“进入内存池”“获得 1 次确认”各自说明了什么？
6. 区块确认越多通常意味着什么？它为什么仍不是绝对不可逆？
7. UTXO 模型如何让节点识别双花？

判断标准：能够从一个具体输入追溯到被消费的输出，并独立算出手续费；解释双花时同时提到节点验证和链历史选择。
