# 第 9 周：把问题变成可复现的链上数据研究

本周回答的问题是：**怎样从公开链上记录得到一个定义清楚、可复核、不过度外推的结论？**

## 学习目标

完成本周后，你应当能够：

- 把宽泛观点改写成包含对象、指标、时间范围和比较基准的可验证问题；
- 区分交易、内部调用、事件日志、合约状态和浏览器标签；
- 确认网络、合约地址、代理实现、ABI、代币精度与区块范围；
- 为活跃用户、收入、流动性集中度等指标写出明确口径；
- 保存来源、查询、清洗规则和局限，使另一位学习者能够复现。

## 核心概念

### 1. 链上数据不是自动生成的答案

链上记录准确表达协议接受的数据，但研究者仍要定义实体、指标与窗口。同一用户可以控制多个地址，合约/机器人也可以发交易；“唯一地址数”不能不加限定地写成“真实用户数”。

### 2. 数据层次

- 区块和交易：谁提交了顶层调用、何时被纳入；
- 调用轨迹：合约执行期间的内部调用，不是独立顶层交易；
- 事件日志：合约主动发出的结构化记录，便于索引；
- 当前状态：在某一区块高度读取的余额、配置和 storage；
- 浏览器标签/解码：第三方提供的解释，需要与地址、ABI 和源码交叉核对。

### 3. 可复现性

一个最小可复现结论至少包含：网络、合约与版本、起止区块、UTC 时间、数据来源、事件/函数、过滤条件、去重口径、单位换算、查询或逐步操作、结果和已知局限。

### 4. 代理和版本

代理地址可能长期不变，而实现代码和业务规则已升级。只看当前已验证源码解释历史数据可能得出错误结论。研究时要把升级区块切分出来，并区分代理、实现和管理合约。

## 实践

本周只读。推荐从一个合约数量较少、事件明确的协议开始；不要同时研究多链和多个版本。

### 实践 A：把观点改写成问题

从以下方向任选一个：

- 活跃地址是否持续增长？
- 收入来自实际使用还是代币激励？
- 流动性或代币持仓是否集中？
- 大额流动性退出时协议是否承压？

使用[链上数据问题工作表](../research/onchain-data-question-worksheet.md)把它改写为：

```text
在 [网络] 上，协议 [具体版本/合约集合] 于 [UTC 日期或起止区块] 期间，
按 [精确定义的指标] 衡量，与 [上一窗口/基准] 相比发生了什么变化？
```

同时写出一个替代解释和一个会推翻初始观点的结果。

### 实践 B：确认研究对象

1. 从协议官方部署文档获得网络与合约地址，不从社交媒体复制地址。
2. 在区块浏览器核对部署交易、创建者、已验证源码与编译信息。
3. 检查是否为代理；若是，记录当前实现、管理员和已知升级区块。
4. 获取匹配版本的 ABI，找出与研究问题相关的事件和只读函数。
5. 检查所有代币的 `decimals`，写出原始整数到展示单位的换算。
6. 把时间范围转换为起止区块，并记录转换方法；时间戳统一使用 UTC。

### 实践 C：采集一个最小数据集

可使用浏览器手工导出、服务商 API、节点 JSON-RPC 或查询平台。无论使用哪种方式，都要：

1. 保存原始来源或查询链接，以及获取日期。
2. 明确选择的事件 topic、合约地址和起止区块。
3. 保留交易哈希、日志索引和区块号，便于去重。
4. 写清失败交易是否计入、内部调用如何处理、代理升级如何分段。
5. 将至少 5 条样本逐条回到浏览器/节点核对解码与数值。
6. 对总量执行一个独立合理性检查，例如与合约状态差值、协议仪表板或另一数据源比较。
7. 若结果不一致，先记录差异，不为了匹配仪表板而偷偷改变口径。

### 实践 D：定义并计算指标

根据问题选择一个主指标和最多两个辅助指标。示例：

- **活跃调用地址**：窗口内直接调用指定入口的唯一 `from`；明确不等于真人用户；
- **协议费用**：按特定事件/状态变化定义的费用，不把交易 Gas 或代币激励混入；
- **持仓集中度**：指定区块高度前 N 个可识别持有地址占比，明确是否排除池、销毁地址、桥和协议金库；
- **流动性退出压力**：设定可验证的退出量与池深/储备对比，明确这是情景而非预测。

记录分子、分母、排除项和单位。先算结果，再尝试一个合理的替代口径，观察结论是否稳健。

### 实践 E：制作复现包

让另一位学习者只依据你的记录完成：

1. 找到同一批合约和区块范围；
2. 获得相同原始记录数；
3. 应用相同过滤和单位换算；
4. 得到允许微小格式差异的相同指标；
5. 找到你列出的 5 条抽样交易。

任何一步无法复现，就回到证据日志补充，而不是只解释口头思路。

## 本周交付物

在 `week-09/` 中提交：

- `research-question.md`：完成的问题工作表、假设、替代解释与反证结果；
- `contract-inventory.md`：网络、地址、代理/实现、版本、ABI、精度与升级区块；
- `evidence-log.md`：按模板记录来源和至少 5 条抽样证据；
- `method.md`：起止区块、指标定义、过滤、去重、换算和复现步骤；
- `result.md`：一个主结论、图/表、替代口径结果、局限与不超过三条下一步。

原始数据较大时只提交可公开重获的来源、查询和校验哈希/摘要，不把 API 密钥或用户隐私数据放入仓库。

## 验收问题

1. 唯一地址数为什么不能直接等同于唯一用户数？
2. 顶层交易、内部调用和事件日志有什么不同？
3. 为什么历史分析必须检查代理升级区块？
4. 代币 `decimals` 使用错误会怎样影响结论？
5. 失败交易和移除的链块应如何处理？口径必须记录在哪里？
6. 怎样验证查询平台解码的数据没有选错事件、地址或网络？
7. 你的主结论在哪个替代口径下最脆弱？
8. 哪一个新结果会让你撤回当前结论？

判断标准：另一位学习者能在不询问你的情况下复现主指标；结论只覆盖声明的网络、版本、区块范围和指标，不外推为项目整体价值。

## 安全提示

- 查询公开链上数据不需要钱包签名。要求授权代币或签署消息的“数据工具”应立即停用。
- API 密钥放在本地环境变量或忽略文件中，不写入查询截图、Markdown 或版本库。
- RPC、浏览器与索引平台都可能延迟、漏数或错误解码；重要结果必须抽样交叉核对。
- 公开地址仍可能关联个人行为。报告采用最小必要原则，不进行无依据的现实身份曝光。

## 离周门槛

把复现包交给另一位学习者。只有当对方能获得相同记录范围、重算主指标，并准确复述你的口径和两项局限时，才进入第 10 周。
