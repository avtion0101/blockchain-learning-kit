# 证据记录表模板

> 用途：让报告中的每个关键结论都能追溯、复核和更新。复制空白行或“单条证据卡”继续填写。
>
> 研究纪律：优先使用原始资料；同时记录支持证据与反证；所有资料都写明版本、发布日期、访问日期、网络和区块高度。社交媒体可以提供线索，但不能单独证明关键结论。

## 1. 研究信息

| 字段 | 填写内容 |
| --- | --- |
| 研究主题 | 【填写】 |
| 核心研究问题 | 【填写为可验证问题】 |
| 协议 / 网络 | 【填写】 |
| 研究截止时间 | 【YYYY-MM-DD HH:mm，时区】 |
| 截止区块高度 | 【填写；不适用则说明】 |
| 合约 / 文档版本 | 【填写】 |

| 本表版本 | 【v0.1】 |

## 2. 来源等级

等级不是“自动可信度”。即使是原始资料，也要检查版本、权限、实现与陈述是否一致。

| 等级 | 来源类型 | 常见示例 | 使用方式 |
| --- | --- | --- | --- |
| A | 可直接验证的原始资料 | 已部署合约、源代码、交易、事件日志、状态证明 | 支撑机制、权限、资金与真实行为 |
| B | 正式规范与治理记录 | 协议规范、标准、已执行治理提案、版本发布记录 | 确认设计意图、版本和变更 |
| C | 安全与事故原始材料 | 审计报告、漏洞披露、事故复盘、补丁 | 验证已知风险；注意审计范围与日期 |
| D | 官方解释材料 | 官方文档、帮助中心、团队公告 | 帮助理解，但要与代码和链上状态交叉核验 |
| E | 独立二手研究 | 学术论文、可靠研究机构、可复现数据分析 | 提供解释和对照；检查方法与利益关系 |
| F | 线索性材料 | 媒体、论坛、社交平台、未署名数据图 | 仅作为待验证线索，不单独支撑关键结论 |

#### 原始内容

- 定位信息：【章节、函数、代码行、事件、表格、时间戳等】
- 简短原文或原始数值：【只摘录核验所需的最短片段；长内容用自己的话概述】
- 上下文：【原文前后讲了什么，是否有条件或例外】
- 自己的释义：【不要加入来源没有表达的判断】

#### 核验过程

1. 我如何确认链接或标识符指向正确对象：【填写】
2. 我如何确认网络、地址、版本和日期一致：【填写】
3. 我用什么独立方式交叉核验：【第二来源、链上查询、代码或手算】
4. 复核结果：【一致 / 部分一致 / 冲突 / 无法核验】
5. 可复现步骤或查询链接：【填写；敏感信息和 API 密钥不得写入】

#### 证据能说明与不能说明

- 它直接说明：【填写】
- 它不能单独说明：【填写】
- 从证据到结论还需要的推理：【填写】
- 关键假设：【填写】
- 局限与潜在偏差：【样本、利益关系、测量误差、版本过期等】

#### 反证检查

- 使用过的反向搜索词：【失败、漏洞、反对、治理争议、版本变更等】

## 8. 完成前检查

- [ ] 每条关键结论都能通过编号回到具体证据
- [ ] 已优先检查协议规范、代码和链上原始数据
- [ ] 已记录网络、地址、版本、日期和区块高度
- [ ] 已区分路线图设想、提案、已接受标准与已上线功能
- [ ] 已记录反证、冲突和无法核验的内容
- [ ] 已说明证据不能证明什么
- [ ] 已保存复现步骤，但未泄露私钥、助记词或 API 密钥
- [ ] 已给可能过期的证据设置复核条件
- [ ] 报告结论没有被表达成投资建议

> 本表只用于研究记录。来源的存在不等于项目安全或资产适合投资；任何结论都受记录日期、版本、数据口径与未知风险限制。
